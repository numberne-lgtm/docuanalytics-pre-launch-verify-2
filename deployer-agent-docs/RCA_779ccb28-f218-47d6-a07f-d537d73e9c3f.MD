## What IS known (platform architecture, not a live probe)
- Emergent production databases are **MongoDB Atlas**, one per app, reached via the `MONGO_URL` system key (platform-managed). This binding is regenerated on every deploy and points at the production Atlas cluster — NOT the preview standalone DB.
- Atlas clusters (including the M0 free tier) are **always deployed as replica sets**, never standalone. Replica sets on MongoDB 4.0+ support multi-document transactions; sharded/Atlas on 4.2+ as well.
- Implication: the production binding is overwhelmingly expected to be a replica set that supports `start_session()` + `start_transaction()`. The preview standalone DB (which does NOT support transactions) is a separate binding and is correctly to be disregarded.

## Read-only test-transaction feasibility
- A transaction cannot be validated read-only. `start_transaction()` only commits/aborts meaningfully around a write, and the mere act of opening + committing a transaction is itself a server interaction that requires write intent to prove support. So a verifying transaction test is **impossible within read-only constraints** — correct to not run one.

## Conclusion
- **Transactions supported: YES (high confidence) by platform architecture** — Emergent prod MongoDB is Atlas, which is a replica set supporting multi-document transactions.
- **UNKNOWN by direct live verification** — my tooling cannot execute `hello`/`buildInfo`, so topology, `setName`, `msg:"isdbgrid"`, and `logicalSessionTimeoutMinutes` were not observed on the live binding.

## Recommended definitive confirmation (outside my read-only tooling)

1. From app code / a one-off script using the production `MONGO_URL`: log `db.command("hello")` (or `client.server_info()`), capturing `setName` / `msg` / `logicalSessionTimeoutMinutes` / version.
2. Guard the patch defensively: wrap the transaction path in a try/except for `OperationFailure`/`PyMongoError` ("Transaction numbers are only allowed on a replica set member or mongos") with a non-transactional fallback, so a standalone binding degrades safely rather than crashing payment crediting.
