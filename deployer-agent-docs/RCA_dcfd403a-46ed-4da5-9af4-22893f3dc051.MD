# RCA — DocuAnalytics AI (docuanalytics.online) PayPal stuck in sandbox

Deployment: pre-launch-verify-2 | Active run: dcfd403a-46ed-4da5-9af4-22893f3dc051 | Mode: READ-ONLY diagnostic (no deploy, no changes)

## Symptom
`GET /api/paypal/config` returns `enabled=true, mode="sandbox", client_id=<sandbox/test id>` after the latest deploy, even though the user set LIVE-slot secrets (PAYPAL_MODE=live + live PAYPAL_CLIENT_ID/SECRET/WEBHOOK_ID).

Live probe (`https://pre-launch-verify-2.emergent.host/api/paypal/config`):
`{"enabled":true,"client_id":"AdrLIW...ur_","mode":"sandbox","currency":"EUR"}`

## Answers to the 4 questions

**(1) Does the production container contain backend/.env, and does it hold TEST or LIVE values?**
YES — `backend/.env` is present (seen in the run's pulled/built source at `/app/scratch/backend/.env`, 1815 bytes). It holds **TEST/preview values**: `PAYPAL_MODE="sandbox"`, and its live-slot `PAYPAL_CLIENT_ID` is byte-identical to its `PAYPAL_SANDBOX_CLIENT_ID` (i.e. a sandbox/test client id). This is definitively proven to be live in production because the endpoint serves `mode="sandbox"` which can ONLY come from this file (the OS env has `PAYPAL_MODE="live"`).
Keys present in the baked `.env`: PAYPAL_MODE, PAYPAL_CLIENT_ID, PAYPAL_SECRET, PAYPAL_WEBHOOK_ID, PAYPAL_SANDBOX_* , ADMIN_TOKEN, SENDER_EMAIL, RESEND_API_KEY, STRIPE_API_KEY, STRIPE_WEBHOOK_SECRET, JWT_SECRET, WEBHOOK_CRON_SECRET, etc.

**(2) Are the keys injected as OS env vars in the prod pod, and is OS PAYPAL_MODE "live" or "sandbox"?**
YES — all present and non-empty in the active run's environment (list_secrets): PAYPAL_MODE, PAYPAL_CLIENT_ID, PAYPAL_SECRET, PAYPAL_WEBHOOK_ID, ADMIN_TOKEN, SENDER_EMAIL.
OS `PAYPAL_MODE` = **"live"** (matches_expected "live"=true, "sandbox"=false).

**(3) For each key, do the FILE value and OS value match? (yes/no)**
- PAYPAL_MODE: **NO** — file="sandbox", OS="live" (directly proven).
- PAYPAL_CLIENT_ID: **YES** — both equal the sandbox/test client id "AdrLIW...ur_" (file serves it; OS matches_expected=true for the same public value). NOTE: this means the OS/Secrets-tab PAYPAL_CLIENT_ID is STILL the sandbox id, not a live PayPal app id.
- PAYPAL_SECRET: **UNVERIFIED** — true secret, not comparable without exposing its value.
- PAYPAL_WEBHOOK_ID: **UNVERIFIED** — same reason.
- ADMIN_TOKEN: **UNVERIFIED** — same reason.
- SENDER_EMAIL: **UNVERIFIED** — not compared to avoid exposing.

**(4) Is the LIVE slot of PAYPAL_MODE equal to "live"?**
YES — the user-set OS secret PAYPAL_MODE = "live".

## Root cause
`backend/server.py` resolves config as `_ENV_FILE = dotenv_values(ROOT_DIR/'.env')` then `X = _ENV_FILE.get('X') or os.environ.get('X')` (lines 29, 44, 50, 54, 55, 59, 63, 64, etc.). The **baked backend/.env FILE takes precedence over the production OS environment variables**. That file was copied from the preview pod into the image and still holds preview/sandbox values (`PAYPAL_MODE="sandbox"`, sandbox client id). So in production the file's `PAYPAL_MODE="sandbox"` overrides the user's OS `PAYPAL_MODE="live"`, and the sandbox client_id is served.

Affected keys (all read file-first, so any prod OS override is shadowed by the baked .env): PAYPAL_MODE, PAYPAL_CLIENT_ID, PAYPAL_SECRET, PAYPAL_WEBHOOK_ID, STRIPE_API_KEY, STRIPE_WEBHOOK_SECRET, ADMIN_TOKEN, SENDER_EMAIL, RESEND_API_KEY, JWT_SECRET, WEBHOOK_CRON_SECRET, EMAIL_VERIFICATION_ENABLED, PUBLIC_BASE_URL. Confirmed-driving-the-symptom: PAYPAL_MODE (and client_id, which is sandbox in BOTH file and OS).

## Secondary finding (important for go-live)
Fixing only the precedence is NOT sufficient: OS `PAYPAL_CLIENT_ID` is itself still the sandbox/test id. If precedence is inverted (OS wins), mode would become "live" but the client_id would come from OS = sandbox id → live PayPal auth would still fail. The user must also save the real LIVE PayPal credentials in the Secrets tab.

## Fixes
1. CODE (E1 / repo): Stop letting the baked `.env` override production env. Either (a) exclude `backend/.env` from the deployed image (.dockerignore / don't COPY it), or (b) invert precedence to `os.environ.get('X') or _ENV_FILE.get('X')`. This is the primary fix for mode=sandbox. Requires a redeploy. (Reproduced in eph sandbox: .env present with PAYPAL_MODE="sandbox"; code confirmed reading file-first.)
2. USER (Secrets tab): Set the actual LIVE PayPal credentials — production OS `PAYPAL_CLIENT_ID` is currently the sandbox/test id. Set PAYPAL_CLIENT_ID / PAYPAL_SECRET / PAYPAL_WEBHOOK_ID to the new live app values (PAYPAL_MODE=live is already correct). Then redeploy.

Note: both are required. Until the CODE fix ships, the baked sandbox `.env` wins regardless of Secrets-tab values.
