## Precedence (proven)
`server.py:29  _ENV_FILE = dotenv_values(ROOT_DIR / '.env')` (ROOT_DIR = backend/).
Every one of the 9 keys resolves **file-first**: `_ENV_FILE.get(X) or os.environ.get(X)`.
Because the `.env` value is non-empty for all 9, the `or` **short-circuits to the FILE value** and the pod's OS-env value is never consulted for these keys.

## How backend/.env reaches the image (proven)

- `Dockerfile.cloudbuild`: `COPY backend/ /app/backend/` (L171); `COPY . /runtime-source` (L258) → `COPY --from=runtime-source /runtime-source/ /app/` (L286). So `backend/.env` is baked into the runtime image verbatim.
- The preview→prod URL rewrite (L37 `sed ... /app/.env`) runs only in the **frontend** stage (`COPY frontend/ /app/` at L32). It does **not** touch `backend/.env`. Backend secrets pass through unmodified from preview.

## (f) Platform behavior
- **Does the platform inject the prod ("live-slot") values into the pod OS env?** YES. `list_secrets` confirms all 9 keys present and non-empty in the active run's OS env. SYSTEM keys (STRIPE_*) are regenerated from prod state every deploy; custom keys come from the Secrets tab / prior prod run. The platform's intended configuration channel is the **pod OS environment**.
- **Is `backend/.env` in the image expected platform behavior?** Only in the mechanical sense that the pipeline does not strip it: `pull_source` copies all of `/app` except `node_modules`/`.git`, and there is no `.dockerignore`, so a committed `backend/.env` from preview is baked in. The platform does NOT rewrite or sanitize `backend/.env` (only the frontend `.env` URL rewrite exists). Relying on a baked `backend/.env` with file-first precedence is an **app-level anti-pattern** that overrides the platform-injected prod secrets — it is not the intended configuration path.

## CONCLUSION — keys effectively running with non-production (TEST/preview/baked) values
All 9 keys run with the value baked into `backend/.env` (preview), because the code is file-first and every file value is non-empty. Specifically:
- **PayPal (mode sandbox, client id TEST, PAYPAL_SECRET, PAYPAL_WEBHOOK_ID)** → TEST/sandbox.
- **ADMIN_TOKEN** → TEST (externally verified).
- **JWT_SECRET** → preview secret (externally verified: a preview-signed JWT validates in prod).
- **STRIPE_WEBHOOK_SECRET, RESEND_API_KEY, SENDER_EMAIL, WEBHOOK_CRON_SECRET** → the preview-baked values, NOT whatever is set in the Secrets tab / OS env.
- **STRIPE_API_KEY** → a **LIVE-prefixed (`sk_live_`) key read from the baked preview `.env`**, not the platform's OS-env Stripe key. This is a secret baked into image layers and should be treated as exposed.

Net: the platform is injecting the correct prod secrets into the pod OS env, but the app ignores them for all 9 keys due to file-first precedence against a baked `backend/.env`.
